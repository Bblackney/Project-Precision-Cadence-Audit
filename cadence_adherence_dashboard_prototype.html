Verified against Salesloft docs, June 2026. The in-app Analytics rates (% On-Time, % Overdue, % Skipped steps) are not exposed by the v2 REST API; the closest endpoint, cadence_stats, returns engagement counts only. Tags show the real source per metric: DIRECT API field · DERIVED rebuilt from /actions + /activities · SNAPSHOT live backlog, point-in-time · EXPORT Analytics CSV only.

Two senses of "overdue", they behave oppositely. Salesloft Analytics % Overdue counts steps completed late (historical: once a step is done late it stays counted, it does not clear when the rep catches up; On-Time + Overdue = 100% of completed steps). The API /actions overdue counts steps currently past due and not yet done (a live backlog that drops out the moment the step is completed). In this dashboard, Overdue % uses the completed-late sense and Avg Days Overdue uses the live-backlog sense.

On-Time denominator excludes skipped steps, and multi-step cadences recalibrate each step's due date from when the prior step was completed.
